# usage-tracker

Usage Tracker

A simple application usage tracker for Hyprland that monitors active application usage and displays daily usage statistics through a GTK4-based widget.

Directory Structure
~/.config/usage-tracker/
├── install.sh
├── usage-tracker.py
├── usage-widget.py
├── usage-tracker.service
└── usage-data.json
usage-tracker.py
Monitors active window changes in Hyprland
Measures active application usage time
Categorizes applications
Creates hourly usage data
Records daily usage data
Stores data in usage-data.json
Can run in the background as a systemd user service
usage-widget.py
Displays daily data from usage-data.json
Uses GTK4 and GTK4 Layer Shell
Displays total daily usage time
Displays hourly usage as a simple square/bar graph
Displays total usage time by category
Lists the most used applications
usage-tracker.service

Runs the tracker in the background within the user's session.

usage-data.json

Usage data automatically generated by the tracker.

usage-data.json should not be edited manually. It is updated by the tracker.

Installation

First, enter the directory:

cd ~/.config/usage-tracker

Make the installation script executable:

chmod +x install.sh

Run the installer:

./install.sh

After installation, the tracker is started as a systemd user service.

Service Status

Check whether the tracker is running:

systemctl --user status usage-tracker.service

Show detailed output:

systemctl --user status usage-tracker.service --no-pager -l

View the actual service configuration:

systemctl --user cat usage-tracker.service

Expected ExecStart:

ExecStart=%h/.config/usage-tracker/usage-tracker.py

View the service configuration directly:

systemctl --user show usage-tracker.service \
    -p Description \
    -p ExecStart
Tracker Monitoring Terminal

To view the tracker's live logs:

journalctl --user -u usage-tracker.service -f

View the last 50 log entries:

journalctl --user -u usage-tracker.service -n 50 --no-pager

View the last 100 log entries:

journalctl --user -u usage-tracker.service -n 100 --no-pager

Restart the service:

systemctl --user restart usage-tracker.service

Stop the service:

systemctl --user stop usage-tracker.service

Start the service again:

systemctl --user start usage-tracker.service
Tracker Process Check

Check the running tracker process:

pgrep -af "usage-tracker.py"

Expected:

python3 /home/bob/.config/usage-tracker/usage-tracker.py
View Usage Data

Data file:

~/.config/usage-tracker/usage-data.json

View the complete file:

cat ~/.config/usage-tracker/usage-data.json

View the JSON in a more readable format:

python3 -m json.tool ~/.config/usage-tracker/usage-data.json

Continuously monitor the data:

watch -n 1 cat ~/.config/usage-tracker/usage-data.json
Usage Data

The tracker stores daily data under days.

Example structure:

{
  "version": 1,
  "updated_at": "2026-09-24T00:30:00",
  "days": {
    "2026-09-24": {
      "total_seconds": 3600,
      "applications": {
        "firefox": {
          "name": "Firefox",
          "seconds": 1800,
          "category": "Information"
        },
        "code": {
          "name": "VS Code",
          "seconds": 1200,
          "category": "Productivity"
        }
      },
      "hourly": {
        "00": 1200,
        "01": 1800,
        "02": 0
      }
    }
  }
}
Open the Widget Manually

Run the widget directly:

python3 ~/.config/usage-tracker/usage-widget.py

or, if executable:

~/.config/usage-tracker/usage-widget.py

Close the widget with:

Ctrl+C
Open the Widget on a Specific Monitor

The widget supports the USAGE_TRACKER_MONITOR environment variable.

For example:

USAGE_TRACKER_MONITOR=DP-1 \
python3 ~/.config/usage-tracker/usage-widget.py

List available monitors:

hyprctl monitors

For example:

Monitor DP-1
Monitor HDMI-A-1

Then:

USAGE_TRACKER_MONITOR=DP-1 \
python3 ~/.config/usage-tracker/usage-widget.py
Run the Tracker Manually

To test the tracker without systemd:

python3 ~/.config/usage-tracker/usage-tracker.py

At startup, you should see:

[usage-tracker] Starting
[usage-tracker] Data: /home/bob/.config/usage-tracker/usage-data.json

Press:

Ctrl+C

to stop it.

If the tracker is already running through systemd, do not start a second tracker manually. Two processes should not write to the same usage-data.json file at the same time.

Quick Test

Open two terminals.

Terminal 1 — Tracker logs
journalctl --user -u usage-tracker.service -f
Terminal 2 — JSON data
watch -n 1 cat ~/.config/usage-tracker/usage-data.json

Then use several applications for a few minutes:

Firefox
↓
Terminal
↓
VS Code
↓
Firefox

Check that the seconds values of the applications increase in the JSON file.

Widget Test

After the tracker has started generating data:

python3 ~/.config/usage-tracker/usage-widget.py

The widget should display the daily usage data.

If there is no data yet:

Usage data not available yet.

may be displayed.

In that case, first check:

cat ~/.config/usage-tracker/usage-data.json

to verify whether the tracker is generating data.

Reload the Service

After changing the code:

systemctl --user daemon-reload
systemctl --user restart usage-tracker.service

Check the service:

systemctl --user status usage-tracker.service --no-pager
Enable Automatic Startup

The installation script enables the service automatically.

To manually enable it:

systemctl --user enable usage-tracker.service

Disable automatic startup:

systemctl --user disable usage-tracker.service
